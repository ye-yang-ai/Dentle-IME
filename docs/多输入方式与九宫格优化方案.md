# 多输入方式与九宫格优化方案

> 实施状态：第一、二阶段已完成。九键已支持单字、词语、连续整句、简拼、全拼混合输入、逐位拼音消歧和分段改词。高度歧义的短码仍可能需要手动选拼音。

## 1. 目标与范围

在现有安卓输入法中加入中文拼音九宫格，并允许用户在拼音 26 键和拼音九宫格之间切换。两种布局共用现有的口腔医学词库、候选词、选词记忆和文本提交流程。当前英文、数字、符号输入继续保留；手写、笔画、双拼和语音属于后续独立输入方案，不包含在本次实现范围内。

建议第一阶段默认仍使用 26 键，九宫格作为可选且可记忆的布局。先保证常用词、单字和口腔术语的九键输入与纠错；连续整句和简拼的九键适配放在第二阶段。

## 2. 改造前实现与问题

- `DentalImeService.renderKeys()` 只生成 QWERTY 字母键和数字符号页；`?123` 切换的是符号页，`🌐` 打开系统输入法选择器。
- `DentalImeService.press()` 把中文拼音输入直接追加为字母串，`updateCandidates()` 把该字母串交给 `PinyinDictionary`。
- `PinyinDictionary` 的查询、整句组合及 `CandidateMemory` 的记忆键都基于字母拼音。词库 `entries` 表按 `pinyin` 建索引，尚无九键数字编码索引。
- 因此，仅更换按键外观无法支持九宫格。按键序列 `64426` 可表示 `nihao`，也可能表示其他字母组合；必须保留数字原码，并提供拼音消歧能力。

## 3. 交互设计

### 3.1 布局选择

在键盘工具区提供布局按钮，打开包含“拼音 26 键”和“拼音九宫格”的简短菜单。选中项有明确标记，选择后立即保存为中文拼音的首选布局，下次打开普通中文文本框继续使用。应用首页的设置页也可提供相同选项，但键盘内入口应始终可达。

中英文切换、数字符号切换、系统输入法切换分别保留独立入口，避免将“键盘布局”“输入语言”“系统输入法”混为一个开关。英文输入先沿用 26 键；数字、电话、日期和密码等输入框按 `EditorInfo.inputType` 优先使用适合的键盘，不受中文布局偏好影响。

切换布局时若已有未提交的拼音，应先让用户选词或取消当前组合，再完成切换；不能默默提交首位候选或丢失组合内容。实现时可以记录待切换布局，在当前组合正常结束后应用，并在按钮上显示待切换状态。

### 3.2 九宫格键盘

采用标准映射：`2 ABC`、`3 DEF`、`4 GHI`、`5 JKL`、`6 MNO`、`7 PQRS`、`8 TUV`、`9 WXYZ`。`1` 可作为常用标点入口，`0` 对应空格；删除、回车、中英文及数字符号入口保持可见。短按 `2` 至 `9` 输入拼音数字码，长按输入对应数字，避免数字输入与拼音输入相互干扰。

保留当前的组合区、候选栏和整句草稿区域。在九键输入时，组合区显示已确定的拼音与未确定的数字码；候选栏显示可上屏的汉字词。另提供横向可滚动的拼音筛选项，显示当前数字码可能对应的拼音，例如输入 `64426` 时可选 `nihao`。用户点选拼音后，候选范围缩小到该拼音。删除键优先撤销本次拼音筛选，再逐位删除数字码；选词后清空九键组合状态。

## 4. 实现方法

### 4.1 拆分输入状态与界面

将中文布局单独建模为 `QWERTY` / `T9`，与现有的中文/英文、字母/符号、Shift 状态分开。布局负责绘制按键和把按键事件转换为输入操作；候选展示、提交、删除、记忆调用尽量共用。`renderKeys()` 的重绘条件应包含布局状态，避免切换后仍显示旧按键。

九键组合状态至少区分：原始数字码、用户已选定的拼音、候选结果、正在编辑的段落。不要把数字码直接塞入现有字母 `composition`，也不要用当前显示文本反推输入状态。候选异步查询需继续使用生成号取消过期结果，布局切换和删除也必须使旧查询失效。

### 4.2 建立数字码索引

在 `tools/generate_pinyin_db.py` 生成词库时，为 `entries.pinyin` 计算 T9 数字码，例如 `nihao -> 64426`。可新增 `t9_code` 列及 `(t9_code, rank DESC, freq DESC)` 索引；简拼若在第二阶段支持，再为 `initials` 建对应数字码索引。随 APK 更新打包数据库，沿用现有数据库版本替换流程。

首阶段新增独立的九键查询接口：按完整数字码查词，也可按数字码前缀取有限条结果，返回词条、真实拼音、权重和领域标记。SQL 只查询编码匹配范围，再按原有词频、专业词权重及用户记忆排序。避免逐位枚举 `2` 至 `9` 的所有字母组合；其数量随长度指数增长。

拼音筛选项从命中的真实拼音去重生成，按最高候选权重排序，并限制初始展示数量。选定拼音后，使用现有字母拼音查询链路获取完整同音候选，包括口腔词条。记忆应始终记录真实拼音和最终词语，避免把 `64426` 这类多义数字码当作现有 `CandidateMemory` 的拼音键。

### 4.3 接入候选与提交流程

为候选保留其来源拼音与数字码消费长度。点击候选、空格选首项、删除及标点提交都按当前布局调用相应输入控制逻辑，最终仍通过 `InputConnection` 提交文本。首阶段只接受完整词条与单字的九键匹配；对未能匹配的数字码显示可恢复、可删除的组合状态，不把数字码误提交为拼音或汉字。

第二阶段再扩展连续整句：在有效拼音音节和词条边界上对数字码做有界搜索，用词频、口腔领域权重和现有词组转移分数排序，限制每一步的候选分支数与总查询时间。候选须保留分段所消费的数字区间，才能支持现有的分段改词、逐段删除和正确回退。简拼及全拼混合输入也应在这一阶段接入，避免首阶段为了覆盖所有组合引入难以维护的状态分支。

### 4.5 第二阶段实现记录

- `tools/build_t9_index.py` 在词库 `entries` 中维护 `t9_initials`，在 `transitions` 中维护同名数字码列，并分别建立索引。`tools/generate_pinyin_db.py` 调用该脚本，因此重新生成词库时会同步重建索引；APK 内的离线数据库已更新。
- `PinyinDictionary.lookupT9()` 先查询完整词条与简拼词条，再查词组转移和有界整句组合。整句组合对数字码子串查询全拼及简拼词条，使用 `SentenceComposer` 的 beam search 控制分支数，并保留每段的数字起止位置和实际字母拼写。全拼路径优先展示，简拼和混拼路径随后补充；九键整句按组合得分保留同前缀候选，避免目标句被前缀去重规则排到后面。
- 同码歧义较大时，候选上方的“选拼音”可逐位选择该数字键对应的字母。确定后，按选定的完整字母串复用现有 26 键查询，覆盖全拼、简拼及混拼。点击整句草稿中的某一段可查看该段候选，选词后只替换该段；空格或点击候选可提交修改后的整句。
- 数字码最长接受 32 位；每次查询限制单词码长度和组合搜索宽度，候选请求在后台线程执行，并用生成号丢弃过期结果。选词记忆仍按实际字母拼写与最终词语记录。

### 4.4 偏好与输入框适配

用单独的本地偏好保存中文布局选择，不放进选词记忆文件，以免“清除选词记忆”同时重置布局。普通中文文本框恢复该偏好；英文、邮箱、网址、密码框使用拉丁键盘，数字、电话、日期框使用相应页面。切换输入框时清理当前组合和过期候选，但不重置用户布局偏好。

## 5. 实施顺序与验收

1. 抽出布局状态及布局菜单，完成 26 键/九宫格切换、持久化和输入框适配。
2. 扩展词库生成脚本和数据库索引，实现数字码精确/前缀查询及拼音筛选。
3. 接入九键组合、候选、提交、删除和选词记忆；保持原 26 键流程可用。
4. 在真机和模拟器中测试普通文本、搜索、聊天、邮箱、密码、数字和电话输入框，检查横竖屏及不同宽度的按键尺寸。
5. 收集九键候选质量与响应时间，再实现连续整句、简拼和混拼。

第一阶段至少验证：`64426 -> 你好`、常见单字、现有口腔术语、同数字码不同拼音的筛选、连续删除与重新输入、布局偏好重启后保持、切换时不丢失未提交内容，以及清除选词记忆后布局偏好仍保留。九键查询应保持按键后候选响应流畅；具体耗时目标以目标安卓设备实测确定。

第二阶段验证：`wohaoxiangni -> 我好想你`、`woyaobaya -> 我要拔牙` 的九键整句，以及 `whxn -> 我好想你`、`woxihn -> 我喜欢你` 的逐位拼音消歧；检查候选分段数字区间、分段替换后拼写和整句上屏。模拟器设备测试共 19 项通过。短码可能对应大量字母串，自动排序无法保证目标整句始终位于首屏，用户可用“选拼音”明确消歧。
