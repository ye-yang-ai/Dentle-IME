# 口腔医学输入法：技术方案与开发条件

## 1. 项目目标与首版范围

开发一款可在安卓手机上安装、启用并跨应用使用的中文输入法，让口腔医学生更容易输入专业术语和生僻字。首版以拼音输入为主，提供口腔医学词库和本地选词记忆；暂不规划账号、云同步、语音输入或服务器。

首版完成的判断标准：

1. 安装 APK 后，用户能在安卓系统中启用并切换到本输入法。
2. 能完成常见中文、英文、数字和符号输入，并在不同应用的文本框中正常工作。
3. 输入口腔专业术语的拼音时，能看到正确的词条候选。
4. 用户反复选择某个词条后，它在相同输入条件下的候选位置能提高；用户可暂停和清除记忆。

## 2. 实现方式

### 2.1 整体结构

```text
安卓应用（Kotlin）
├─ 输入法服务：接收按键、管理输入状态、向当前文本框提交文字
├─ 键盘界面：按键、拼音组合区、候选词栏、输入法切换入口
├─ 中文输入引擎：拼音解析、查词、组词及基础候选排序
├─ 口腔医学词库：术语、拼音、基础词频及版本
├─ 本地记忆：用户已选词条的次数、最近使用时间及排序权重
└─ 设置界面：启用指引、学习开关、记忆词管理与清除
```

安卓端使用 `InputMethodService` 接入系统输入法框架，通过 `InputConnection` 向其他应用的文本框提交文字。用户必须在系统设置中主动启用和选择本输入法。中文转换优先评估接入开源 Rime 引擎（librime），而不是从零开发拼音解析和组词。Rime 是引擎，不包含本项目所需的完整产品界面。集成时需验证 Android 构建、JNI 接口、包体积、启动耗时及组件许可证。Trime 可作为安卓端集成方式的参考；直接复用其源码须遵守 GPL-3.0 许可。

### 2.2 专业词库

词库每条至少包含“术语、拼音、基础权重”。先整理口腔基础医学、牙体牙髓、牙周、口腔颌面外科、修复和正畸等高频术语，再由具备专业知识的人员校对字形、读音、多音字和同义写法。确认词库来源及再分发许可后随 APK 发布；后续更新方式在首版验证后决定。

### 2.3 记忆功能

首版以“用户主动选中候选词”为学习事件，只在设备本地保存词条标识、选用次数和最近使用时间。候选排序结合引擎基础权重、专业词库权重和个人使用频率；具体权重应通过真机输入测试调整，避免高频误选词长期占据首位。使用 Room 管理本地结构化数据，提供学习开关、删除单词记录和清空全部记忆。

不保存完整输入句子、密码或剪贴板内容。密码字段、敏感输入类型及应用要求禁止个性化学习的字段停止学习，并避免在候选栏暴露敏感内容。还需明确配置安卓自动备份规则，避免个人记忆数据库意外进入云备份。

## 3. 可行性分析

| 方面 | 判断 | 主要工作或风险 |
| --- | --- | --- |
| 安卓系统接入 | 可行，系统提供输入法服务框架 | 处理不同应用的文本框、输入类型、键盘生命周期和切换体验 |
| 中文拼音输入 | 可行，可接入现有引擎 | Rime 的 Android/JNI 集成、构建维护、性能和依赖许可需要验证 |
| 口腔词库 | 可行，也是产品价值的关键 | 词条来源、校对质量、多音字和与通用词的排序平衡 |
| 本地记忆 | 可行，无需云服务器或 AI 模型 | 选词统计、排序效果、敏感字段排除及用户删除控制 |
| 安装分发 | 可行，可生成签名 APK | 真机兼容性测试、签名密钥保管；公开发布另需满足渠道要求 |

总体判断：技术上可行。最大的不确定性不是“能否显示一个键盘”，而是中文输入体验能否达到日常可用，以及专业词库是否准确。建议先完成一个小规模术语词库的真机原型，再扩大词库和优化排序。

## 4. 开发条件

### 软件

- Windows 10/11 64 位开发电脑、Android Studio、Android SDK、Kotlin、Gradle、Git。
- 若接入 librime，需 Android NDK、CMake 和相应的 C++/JNI 构建配置。
- 调试工具：Android Studio 的 Logcat、设备管理器和 Android Emulator；真机调试需开启开发者选项及 USB 调试。
- 首版不需要服务器、数据库服务、AI 训练环境或独立显卡。

### 硬件

- 官方 Windows 最低要求：仅运行 Android Studio 为 8 GB 内存，连同模拟器为 16 GB 内存；推荐 32 GB。磁盘可用空间分别至少 8 GB / 16 GB，建议 SSD 留出 32 GB 以上。
- 使用模拟器需 CPU 虚拟化支持并在系统中启用。电脑资源有限时，可优先使用安卓真机调试。
- 至少准备一台安卓手机，实际测试安装启用、输入手感、密码框、搜索框和多个应用中的输入行为。

## 5. 建议实施顺序

1. 配置 Android Studio、SDK、真机调试，运行最小安卓应用。
2. 建立最小输入法服务，完成启用、切换、按键及文本提交。
3. 接入并验证中文输入引擎，完成通用拼音输入。
4. 加入口腔术语词库，校对并测试候选质量。
5. 加入本地记忆及隐私控制，完成跨应用真机测试。
6. 生成签名 APK，进行小范围试用并根据反馈调整词库和排序。
